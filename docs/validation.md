## 本项目启动器的在线验证

环境：macOS，Python 3.14，`everos-mcp==0.1.1`，EverOS Cloud。使用专门的演示 user/project 范围，内容为合成接力规则，不上传私人聊天。

流程：

1. 生成本地配置，运行 `serve.py --check`，核对 scope 并确认不输出 Key。
2. MCP 进程 A 调用 `add_memory(wait=true)` 保存随机项目标记和“测试通过仍需人工核对、未确认前不发布”的演示规则。
3. 独立启动 MCP 进程 B，用同一配置调用 `search_memory`，命中进程 A 保存的随机标记。
4. 进程 A 调用 `forget_session`，服务返回删除 1 条当前连接保存的记录。该调用不承诺删除 profile / skill。

结果：`written=true`，`retrieved=true`；清理收到 `Deleted 1 stored item(s)`。后续仅加强了验收脚本对这条清理回复的检查，没有重新写入测试数据。

这部分是**独立 MCP 进程之间的后端接力验收**，不能代替上面新增的真实模型客户端验收。配置方式对照本机 CLI help 与两家官方 MCP 文档。

## 离线检查

6 项 unittest 通过：

- Claude JSON 与 Codex TOML 的启动命令、参数和设置路径完全一致，包含带空格的路径。
- 虚拟环境 Python 的软链接路径被保留，不会解析成缺少依赖的系统解释器。
- 继承的 user、旧服务地址和固定 session 不会覆盖显式配置。
- 本地设置文件权限受限、已有文件拒绝覆盖。
- 非法身份、含凭据 URL 和无 Key 的 Cloud 配置被拒绝。
- 自托管地址可以不提供 Cloud Key。

另外，直接使用生成的 Claude JSON 和 Codex TOML 各自启动上游 MCP，均完成 initialize/list_tools 握手并列出 7 个工具。这一步使用不联网的占位凭据，只证明生成的命令可启动与发现工具，不证明客户端模型已调用或云端认证成功。
